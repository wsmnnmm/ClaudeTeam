## 一句话结论

第九章“API 超市”对老板当前最有用的内化，不是记住更多 API 平台，而是把 AI 产品图接单服务设计成一套可报价、可切换、可验收、可解释风险的供应链：主链路先用 gpt-image-2 中转跑通客户结果，备用链路用于救火和横评，最终用成本、质量、速度、稳定性决定是否接单与怎么交付。

## Founder OS 标注

- 当前阶段：MVP。
- Stage exit evidence：至少 1 个真实客户需求或样单，用主链路生成可交付图片；同时完成 1 次备用链路对照，能说明为什么选主链路或为什么不接单。
- 今天最小证据动作：选 1 个老板真实接单场景，生成同一 prompt 的主链路样图，记录耗时、成本、失败信息、客户是否可用。
- 不做什么：不搭“万能生图平台”；不承诺所有风格都能做；不把跑通 demo 当成市场验证；不公开 API key、token、客户原图或私密素材。
- 老板必须参与：决定接哪类单、给出样单素材、确认可接受的交付质量、授权是否付费测试备用 API。

## 老板内化版：怎么用 API 超市接 AI 产品图单

### 1. 先定义“货架”，不是先写代码

老板要把 API 当成可采购的供应商货架：

| 货架角色 | 当前建议 | 用途 | 不能承诺 |
| --- | --- | --- | --- |
| 主链路 | gpt-image-2 中转 | 默认接单、默认打样、默认交付 | 不承诺永不失败、不承诺最低成本 |
| 备用链路 | Replicate / fal / 火山 | 主链路失败、风格不稳定、速度不够时切换 | 不承诺输出完全一致 |
| 横评链路 | OpenRouter 或其他聚合入口 | 看模型选择、文本理解、辅助 prompt 改写 | 不等于最终图片质量 |
| 人工兜底 | 老板或执行者人工筛图 / 改 prompt / 退单 | 防止坏图直接交付客户 | 不承诺全自动无人工 |

老板今天不要问“哪个 API 最强”，要问：这个客户的图，用哪个链路能在可控成本和时间内交付到可接受质量。

### 2. 接单前必须问 5 个问题

每个客户需求进入 ProductLab 前，先填这 5 个字段：

1. 客户要的结果：产品主图、种草图、广告图、头像、海报、素材扩图，必须只选一个主结果。
2. 输入素材：客户是否有原图、品牌色、参考图、文案、尺寸要求。
3. 可接受质量：客户要“能发朋友圈/小红书”还是“电商详情页正式用”。
4. 交付时限：10 分钟打样、当天交付，还是多轮精修。
5. 失败边界：如果 API 出错、人物/文字/产品细节变形，是否允许人工修、换链路、延期或退款。

没有这 5 个字段，不进入 API 选择；否则会把技术实验误当成接单。

### 3. API 选择矩阵

| 维度 | 主链路 gpt-image-2 中转 | Replicate | fal | OpenRouter | 火山 |
| --- | --- | --- | --- | --- | --- |
| 质量 | 先作为默认质量基线 | 适合找特定开源模型/风格 | 适合速度型模型和图像工作流 | 更适合文本/多模型路由与 prompt 辅助 | 适合国内可用性和合规备选 |
| 速度 | 以真实样单计时为准 | 模型差异大 | 通常适合快速试验 | 取决于转接模型 | 以国内网络和账号配置为准 |
| 成本 | 作为报价基线 | 适合按模型比较单张成本 | 适合做批量成本对比 | 适合模型路由成本观察 | 适合作为国内供应商成本对照 |
| 稳定性 | 当前默认主链路，需要保留错误原文 | 受模型维护和队列影响 | 受平台/模型可用性影响 | 受上游模型和路由影响 | 受账号、地域、审核和接口策略影响 |
| 接单用途 | 默认打样与交付 | 风格补充、失败替代 | 快速试样、速度横评 | prompt 改写、模型候选研究 | 国内备用、客户敏感场景备选 |

ProductLab 验收重点：不要口头说“备用链路很多”，必须至少做一次同一需求的主链路与一个备用链路对比，记录差异。

## AI 产品图接单 SOP

### Step 1：需求卡

每单先建一张需求卡：

```text
客户类型：
目标图：
输入素材：
尺寸 / 平台：
参考风格：
不可接受项：
交付时间：
报价假设：
主链路：gpt-image-2 中转
备用链路候选：Replicate / fal / OpenRouter / 火山 / 人工兜底
验收人：老板 / 客户 / 执行者
```

### Step 2：主链路打样

- 用 gpt-image-2 中转生成 1 张最小样图。
- 记录 prompt、生成时间、成本估计、成功/失败状态。
- 若失败，保留错误原文，不批量重试，不把失败原因写成“网络不好”这种空话。

完成证据：样图路径、prompt 路径、耗时记录、老板是否认为可给客户看。

### Step 3：备用链路横评

触发条件满足任一条，就跑备用链路：

- 主链路失败或超时。
- 主链路质量不能满足客户目标。
- 客户强调国内可访问、稳定、速度或合规。
- 老板需要报价前知道成本上下限。

横评只看 4 个指标：

1. 成本：单张多少钱，是否可批量。
2. 质量：产品是否变形，文字是否可用，风格是否匹配。
3. 速度：从提交到可下载用多久。
4. 稳定性：失败率、错误是否可解释、是否容易复现。

### Step 4：交付判定

| 判定 | 条件 | 老板动作 |
| --- | --- | --- |
| GO | 主链路样图可用，客户目标清楚，失败边界可接受 | 接单或发样图报价 |
| TRY | 主链路可打样但质量不稳，需要备用链路或人工修 | 只承诺试做，不承诺固定效果 |
| NO-GO | 客户要求过高、素材不足、稳定性不可控、涉及敏感/侵权 | 不接或要求客户补素材/改目标 |

### Step 5：交付复盘

每单结束后只沉淀 6 个字段：

- 客户类型。
- 最终用哪条链路。
- 单张成本与耗时。
- 客户是否接受。
- 失败或返工原因。
- 下次是否可复用为模板。

这 6 个字段比“我们会很多 API”更重要，因为它能形成报价和选型经验。

## WebsiteChuhai 出海军师团 SOP

WebsiteChuhai 的内化目标：把 API 超市思维用于海外产品/服务包装，而不是只做技术选型。

### 1. 出海定位问题

军师团看到一个 AI 图片服务方向时，先判断：

- 海外用户买的是“图生成能力”，还是“更快拿到能卖货的产品图”。
- 目标渠道是 Etsy、Shopify、Amazon、Pinterest、Instagram、Reddit，还是独立站。
- 客户更在意低价、风格、速度、隐私，还是批量稳定。
- 竞争对手是否已经把某类 API 能力包装成模板化服务。

### 2. 出海服务包结构

建议包装为三档，不先做 SaaS：

| 档位 | 交付 | 适合客户 | API 策略 |
| --- | --- | --- | --- |
| Starter | 1 个产品 3 张图 | 测试需求的小卖家 | 主链路即可，人工筛图 |
| Batch | 10 个产品批量图 | 有 SKU 的小店 | 主链路 + 备用链路成本横评 |
| Custom | 风格模板 / 品牌套图 | 有明确品牌要求的客户 | 主链路 + 特定模型/平台 + 人工审核 |

### 3. 军师团输出模板

```text
海外目标客户：
销售渠道：
客户要买的结果：
推荐服务包：Starter / Batch / Custom
默认 API 链路：
备用 API 链路：
最大交付风险：
老板今天最小验证动作：
不建议做的功能：
下一步证据：客户回复 / 样图反馈 / 付款 / 转介绍
```

### 4. WebsiteChuhai 的验收标准

- 能说清楚服务卖给谁，不是“海外用户”。
- 能说清楚客户买的是业务结果，不是 API 名词。
- 至少有 1 个渠道和 1 个客户场景。
- 至少有 1 条备用链路或人工兜底。
- 能判断老板今天该发样图、发报价、找客户访谈，还是先不做。

## 今天最小证据动作

老板今天只做 30-60 分钟，不扩成平台建设：

1. 选一个真实或半真实客户场景：例如“小红书 AI 产品图接单服务，帮一个小商家把一张产品图变成可发种草图”。
2. 写一张需求卡：目标图、输入素材、参考风格、交付时间、不可接受项。
3. 用 gpt-image-2 中转生成 1 张样图，记录 prompt、耗时、是否成功。
4. 若主链路失败或质量不稳，只选一个备用链路做对照，不同时测 5 个平台。
5. 让老板给结论：这张图能不能给客户看，客户会不会愿意为 3 张图付一个小额体验价。

完成证据：

- 一张样图或失败错误原文。
- 一条 prompt 记录。
- 一条成本/耗时记录。
- 老板一句 GO / TRY / NO-GO 判断。

## 不做清单

- 不做完整 API 聚合平台。
- 不做多模型排行榜文章。
- 不承诺“所有客户图都能生成”。
- 不批量消耗额度试错。
- 不把客户原图、API key、token、账号、私密链接写进群聊、普通文档或 memory。
- 不把“技术跑通”当成“有人愿意付费”。

## 给 manager 的合并建议

如果要合并成最终 artifact，建议拆成两块：

1. 老板内化版：强调接单前 5 问、主/备链路、GO/TRY/NO-GO、今天最小证据动作。
2. WebsiteChuhai SOP：强调海外客户、渠道、服务包、API 供应链、交付风险。

ProductLab 验收只看一件事：老板看完后，今天能不能拿一个具体图单做一次可记录的供应链测试，并知道什么情况下接单、试做或拒单。
