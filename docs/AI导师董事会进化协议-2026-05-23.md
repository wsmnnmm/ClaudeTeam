# AI 导师董事会进化协议

时间：2026-05-23
范围：AI 刘小排、AI 亦仁、TODO002、WebsiteChuhai、ProductLab、WorkAssistant

## 1. 定位

AI 刘小排和 AI 亦仁不是普通 worker，也不是漂亮顾问材料来源，而是团队的 Mentor Board。

- AI 刘小排：产品、MVP、技术实现、增长动作、出海工具站、指标设计。
- AI 亦仁：商业判断、机会取舍、目标用户、付费意愿、团队节奏、是否该停。
- TODO002：导师网关，负责 DeepSea 浏览器、导师脚本、顾问卡、loop-state。
- 主责团队 manager：负责把导师建议翻译成任务卡、门禁、SOP 补丁和老板可读结论。
- worker：只执行 manager 翻译后的任务，不执行导师原文。

## 2. 触发条件

满足任一条件，manager 必须考虑进入导师董事会闭环：

- 产品方向、MVP、商业取舍不清。
- 用户反馈具体，但团队不知道如何转动作。
- worker 连续 30 分钟没有真实证据或越改越乱。
- 同一任务返修 3 轮仍无净进步。
- 团队产出很多文档，但真实验证很少。
- 老板纠偏超过 3 次，说明团队判断模型需要升级。
- 出现“是否继续做、是否收窄、是否暂停”的高杠杆判断。

## 3. 标准闭环

```text
Issue
-> Evidence Pack
-> Mentor Ask: AI 刘小排 / AI 亦仁
-> Manager Translation
-> Decision / Task / Gate / SOP Patch / Anti-pattern
-> Execution
-> Verification
-> Result Pack
-> Reask or Close
```

导师闭环不以“导师回复了”为完成，只以团队行为发生改变为完成。

## 4. 输入包

给导师的问题必须包含：

```text
项目：
主题：
当前 owner：
问题类型：product / bug / growth / strategy / ops / review
背景事实：
当前证据：
已尝试动作：
不做什么：
希望导师回答什么：
```

如果有图片、截图、盲测结果、用户反馈、PR、日志，必须进入 evidence pack。导师不能直接打开本地路径，manager 必须提供可见摘要或上传图片。

## 5. 输出门禁

每次导师反馈必须被 manager 翻译成以下五类之一：

- Decision：做 / 不做 / 收窄 / 暂停，附理由和代价。
- Task：owner、完成证据、验收指标、截止时间、不做什么。
- Gate：新增机器门禁或人工验收门禁。
- SOP Patch：更新团队 SOP、skill、manager 规则或 worker 规则。
- Anti-pattern：沉淀反模式，说明以后触发时如何自动避坑。

没有翻译摘要、没有 owner、没有完成证据，导师卡不能进入执行。

## 6. 双导师分工

默认先问 AI 刘小排，再问 AI 亦仁：

- 刘小排回答“怎么做”：产品形态、实现路径、指标、增长动作、最小实验。
- 亦仁回答“该不该”：目标用户、商业价值、付费意愿、是否过度优化、是否该停。

入口纠偏：

- AI 刘小排和 AI 亦仁是 DeepSea 中两个独立入口，不是一个入口里的两个署名。
- 问刘小排时只生成刘小排问题文件，只保存刘小排顾问卡。
- 问亦仁时只生成亦仁问题文件，只保存亦仁顾问卡。
- 禁止写“AI 刘小排 / AI 亦仁回答”“两位导师共同回答”这种混合 prompt。
- manager 只能在两张独立顾问卡都返回后写合并判断。

两位意见冲突时，manager 不许直接平均。必须产出：

```text
冲突点：
刘小排判断：
亦仁判断：
现场证据：
推荐选择：
代价：
需要老板拍板：
```

## 7. 回问规则

禁止重复空问。只有出现新执行证据时，才允许二次问导师：

- 新版本截图或录屏。
- 新 prompt / PR / diff。
- 真实用户反馈。
- 盲测统计。
- 付费意向或成交信号。
- 失败复盘和反证。

二次问必须带 `上次导师建议 -> 执行动作 -> 结果 -> 新问题`。

## 8. 老板视角

老板只看：

- 两位导师的共识或分歧。
- manager 推荐结论。
- 今天该做的最小验证动作。
- 哪个团队 owner 接手。
- 完成后看什么证据。
- 是否需要老板拍板。

老板不看：

- 导师长文原文。
- worker 过程碎片。
- 没有 evidence pack 的追问。
- 没有执行结果的二次问。

## 10. 组织升级要求

从今天起，AI 导师层不再只是 Product / WebsiteChuhai 的产品顾问，也要参与团队本身的进化：

- 每周复盘“本周最消耗老板的 1 个任务”，问导师如何减少老板参与。
- 每周复盘“本周最大产品/商业机会”，问导师是否该下注。
- 每周复盘“本周最大返工”，问导师应该新增什么 gate。
- 每次复盘都必须更新至少一个：SOP、gate、反模式、任务模板、manager 身份规则。

目标不是让导师多说话，而是让团队每周变得更少需要老板纠偏。
