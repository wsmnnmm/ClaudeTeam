## 核心判断

团队当前最大问题不是能力不足，而是规则没有生命周期。新规则不断叠加，旧规则不退出，AI 员工每次都在过期、重复、冲突的文本里找行动依据，所以会“看起来在干活，实际上不清醒”。

第一指标改成：老板人肉纠偏率。即老板为了同一个任务重复解释、手动修正、追问证据的次数。任务数、回执数、群消息数都不是清醒指标。

## 规则分层

- Identity：只保“我是谁、边界、硬红线、索引”。少变。
- SOP：按任务类型描述“通常怎么干”。中频更新。
- Task Gate：把“必须”变成脚本、账本、健康检查、提交前检查。高优先级机器化。
- Fleet Health：只做监控和暴露，不替 manager 做判断。
- Mentor Loop：只在有新证据时触发，用来改 SOP/门禁，不直接当执行结论。

责任链固定为：SOP 指导 Action，Action 产生 Artifact，Artifact 触发 Gate，Health 暴露异常，Mentor 改进 SOP。

## 立刻删除

- 过期时间口径：上周、昨天、今天继续、某轮临时安排，除非带绝对日期和仍有效条件。
- 模糊形容词：优雅、高质量、认真、稳一点、像设计稿，若没有验收指标就删除或改成指标。
- 重复身份声明：多个文件反复描述同一岗位身份，只保 claudeteam.toml + 三层配置索引。
- 聊天完成模式：只说“已完成/已推进/待确认”但没有 artifact/local_id/message_id 的口径全部作废。
- 混合导师入口：任何“AI 刘小排 / AI 亦仁一起回答”的模板作废。
- 归档规则直读：`manager-详细规则归档`、`worker-详细规则归档` 只作历史证据，不进入默认读取顺序。

## 合并压缩

- 同类派活/回报/验收写法合并到团队运行契约或任务控制 SOP。
- 团队专属硬边界保留在团队服务契约。
- 任务型经验沉淀到 SOP 或 memory card，不再塞回 claudeteam.toml。
- 跨团队规则统一引用 Cross-Team Flow，不在四队各写一套近似但不同的说法。

## 转成机器门禁

- 已完成/待验收必须 artifact 存在：已落地到 task/send/fleet-health。
- AI 导师请求必须单导师入口：已落地到 mentor-loop questionGate。
- 云上回传必须回源侧：已落地为 TODO002 return outbox + source pull/import。
- UI 页面还原必须有截图/预览/对比证据：下一步优先在工作分身团队落脚本门禁。
- 规则清理必须有日志：下一步建立 `规则清理-<团队>-Vn.md`，写删除、合并、转门禁理由。

## 保留为 manager 判断

- owner、优先级、是否继续/暂停。
- 方案取舍、架构选型、业务含义。
- 老板纠错后的唯一新口径。
- 导师建议采纳/不采纳理由。
- 哪些模糊需求需要老板亲自定义“好”的标准。

## 老板必须亲自做

- 定义“什么叫好”：页面还原达标样例、产品价值主张、关键体验标准。
- 方向和机会判断：产品要不要做、目标用户是谁、是否值得继续。
- 系统宪法级规则：四队服务契约、团队边界、哪些工作必须解放出去。
- 敏感授权动作：登录、扫码、API key、付费、绑卡、组织授权。

## 一周最小验证

1. Owner：WorkAssistant manager。动作：生成 `规则清理-工作分身团队-V1.md`，把活跃规则、归档规则、待删规则列清楚。证据：文件存在并被三层索引引用。验收：默认读取顺序不再读归档详细规则。
2. Owner：ClaudeTeam。动作：把“归档非 active、冲突时活跃配置和服务契约优先”写进 manager identity 和四队索引。证据：identity 测试与四队索引 diff。验收：manager wake prompt 可读到规则生命周期门禁。
3. Owner：WorkAssistant + ClaudeTeam。动作：给 UI 页面还原增加截图/预览证据门禁。证据：无截图的 UI 交付会被阻断或 fleet-health 拉红。验收：一条真实 UI 任务不再需要老板口头提醒“给我看图”。
4. Owner：各队 manager。动作：记录老板人肉纠偏率。证据：每个任务记录纠偏次数和纠偏主题。验收：一周后拿 3 个任务样本回到 AI 刘小排复盘。
