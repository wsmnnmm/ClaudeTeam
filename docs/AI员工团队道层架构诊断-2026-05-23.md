# AI 员工团队道层架构诊断

时间：2026-05-23
范围：Work Assistant、Product Lab、TODO002、WebsiteChuhai、本地与云上快照

## 0. 一句话结论

当前系统的问题不是“员工不够努力”，也不是“老板没写好逻辑地图”，而是 AI 员工组织还停在“群聊派活 + 文档 SOP + 任务账本”的半自动阶段。要让老板真正解放双手，必须把关键 SOP 升级成机器强制的控制平面：没有真实证据不能流转，没有唯一 owner 不能多队并行，没有 stable baseline 不能自修复，没有新事实不能刷群，没有新鲜心跳不能声称云上可接管，没有 AI 导师董事会闭环就不能说团队在持续进化。

## 2. 根因不是提示词，而是组织系统缺 7 个硬结构

### 2.1 SOP 文档化，但没有机器化

四队已经有大量 SOP：任务控制平面、UI 批量改造、老板视角协议、跨团队门禁、Reality Time Gate。问题是这些主要写在 `claudeteam.toml` 和 docs 里，依赖 manager 自觉执行。

真正需要的是：任务状态流转时由系统强制检查。

例子：

- `待验收` 前必须 artifact 存在。
- UI 任务 `待验收` 前必须截图非白屏、尺寸正确、有预览链接、有 data-source 说明。
- “云上可接管”前必须远端 heartbeats 新鲜、remote snapshot 新鲜。
- “已跨团队投递”前必须目标团队 inbox local_id / task_id / message_id 存在。

### 2.2 manager 既是前台又是执行线程

老板要的是“主管随时空转等待响应”，但实际 manager 经常被迫做长复核、长截图、长排查、长总结。超过 1 分钟的事没有被系统自动剥离成 worker Run，导致老板只能不断问“进度如何”“效果图呢”。

### 2.3 worker 输出没有被强制转成 Run

现在很多 worker 回报像聊天：“已完成”“继续监控”“待验收”。真正需要的是结构化 Run：

```text
Task:
Run:
本轮目标:
新增事实:
证据:
Artifact:
已排除:
风险:
下一步:
是否需要老板:
```

缺任何关键字段，都不能推进状态。

### 2.4 manager_watch 把“等待验收/等待老板/已交付待判定”当成 worker 超时

Product Lab 的 179 条超时告警说明 watch 机制在制造噪音。任务状态机没有区分：

- worker 正在执行
- worker 已交付，manager 待验收
- manager 已验收，老板待拍板
- 缺输入，不应继续
- 已终止，待归档

这导致 watch 一直催“已交付等待判断”的任务，老板看到的是忙乱而不是闭环。

### 2.5 多团队并行缺唯一主责

Work Assistant 和 Product Lab 都卷进 UI 任务后，ProductLab 既被当作协作支援，又被当作执行团队。跨团队没有严格的 source-of-truth：

- 谁拥有任务？
- 谁能改代码？
- 谁只做对比/策略/评审？
- 哪张图是唯一目标？
- 哪个 artifact 是 canonical？

没有这些，跨团队只会放大上下文熵。

### 2.6 云上被当作“活团队”，实际是“守护进程活着”

Product Lab 云上、TODO002 云上 health 显示 router/watchdog 活着，但员工心跳过期。云上应该被明确标成：

- hot：可 5 分钟内接管
- warm：守护进程活着，但员工需唤醒
- cold：只能作为快照/冷备

当前云上多处属于 warm/cold，不能在老板面前说成“云上团队稳定处理”。

### 2.7 AI 导师没有升格为董事会机制

AI 刘小排和 AI 亦仁不应该只是“遇到问题问一下”的外部问答入口，而应该是团队的 Mentor Board：

- AI 刘小排偏产品、MVP、实现路径、增长动作、工具站、指标设计。
- AI 亦仁偏商业判断、机会取舍、目标用户、付费意愿、团队节奏、是否该停。

当前已有导师闭环工具，但缺少组织级规则：

- 哪些问题必须升级给导师？
- 导师反馈由谁翻译成任务卡？
- 导师建议如何进入 SOP / skill / memory / gate？
- 执行后带什么新证据回问导师？
- 哪些导师建议被采纳、未采纳、为什么？
- 导师层如何反向训练 manager 和 worker，而不是只产一份顾问卡？

没有这层，团队会“问过大咖但还是旧团队”：顾问卡变成漂亮文档，员工执行方式没有进化，老板仍然要在群里纠偏。

## 3. WebsiteChuhai 为什么体感最好

不是因为它没有问题，而是它的任务形态更接近 AI 当前最擅长的工作：

- 输入是老板的想法、朋友反馈、盲测结果、导师建议。
- 输出是策略包、视觉卡、行动表、反证和下一步。
- 它不直接承诺“代码已完成/页面已还原”。
- 它在配置里明确写了“只交付 Strategy Package，不替 Product Lab 宣称产品已完成”。
- 它有清楚的外部导师边界：导师原文不是交付，manager 必须翻译成策略包或任务卡。

这说明“好用团队”的核心不是更会干活，而是边界更窄、产物更像决策支持、验收更靠语义质量而非像素/工程事实。

## 4. 道层架构目标：从群聊员工升级成 AI 组织操作系统

### 4.1 Boss Freed Mode

老板只处理 4 类事：

- 方向：做不做、优先级、商业目标。
- 审美：P2 级别偏好、品牌味道、最终观感。
- 授权：账号、支付、密钥、外发、部署。
- 例外：系统触发红色事故、无法自行裁决。

老板不再处理：

- worker 是否读消息。
- artifact 在不在。
- 截图是不是白屏。
- 哪个旧标注作废。
- 哪个 manager 该催谁。

### 4.2 Mission Lane

每个任务只进入一个 lane：

- Work Execution Lane：公司项目功能迭代、bug、联调、页面还原。
- Product Lab Lane：产品取舍、MVP、支付/Auth/上线、能收钱闭环。
- WebsiteChuhai Lane：出海策略、SEO、增长、落地页打法、策略包。
- TODO002 Lane：学习、导师、真需求、课程到项目映射。

跨团队只能输出输入包，不能共享主责。

### 4.3 Issue / Run / Artifact / Gate

每条老板指令先变 Issue。
每个 worker 动作是 Run。
每轮 Run 必须产 Artifact 或 Blocker。
每次状态流转必须过 Gate。

群聊只是 UI，不是状态源。

### 4.4 Evidence Kernel

新增系统级证据内核，所有团队共用。

必须支持：

- artifact path exists
- image exists and not blank
- screenshot viewport matches
- preview URL present
- task status allowed transition
- remote snapshot freshness
- worker heartbeat freshness
- cross-team delivery receipt
- stale artifact invalidation

### 4.5 Incident Mode

一旦触发以下条件，停止继续优化，进入事故模式：

- 老板 30 分钟内纠偏 >= 3 次。
- 同一任务返修 >= 3 轮仍无净进步。
- 产生 P0 回退。
- 超时告警重复 >= 3 次。
- artifact 缺失但任务标待验收/完成。
- worker/manager 说法与证据矛盾。

事故模式只允许三件事：

1. 锁 stable baseline。
2. 产一页事故恢复卡。
3. 等 owner 重新发起下一轮。

### 4.6 Mentor Board

新增 AI 导师董事会层，固定由 TODO002 作为导师网关承载 DeepSea 浏览器和导师脚本，AI 刘小排 / AI 亦仁作为外部高阶判断源，其他团队只提交 evidence pack，不直接把导师原文当任务。

标准闭环：

```text
问题触发 -> evidence pack -> AI 刘小排 / AI 亦仁 -> manager translation
-> 任务卡 / SOP补丁 / gate补丁 -> worker execution -> verification
-> result pack -> 必要时二次问导师 -> 团队记忆更新
```

导师层必须产出五种可落地资产之一：

- Decision：做 / 不做 / 收窄 / 暂停。
- Task：明确 owner、完成证据、验收指标、不做什么。
- Gate：新增机器门禁或人工验收门禁。
- SOP/Skill Patch：把经验写进可复用流程。
- Anti-pattern：沉淀“以后禁止这么做”的反模式。

导师原文不是交付。合格交付必须是：导师卡 + manager 翻译摘要 + 执行任务卡 + 验收证据 + 是否需要二次问导师。

## 5. 可落地升级顺序

### P0：先让系统不再骗你

- `claudeteam task done/review` 增加 artifact 存在性检查。
- UI 任务状态从 running 到 reviewing 前，必须有四证字段。
- fleet-health 报告新增“artifact missing but task claims done/reviewing”红线。
- manager_watch 不再对 `待验收/待老板/已终止/待归档` 任务重复发 worker 超时。

### P1：让 manager 真正空转

- 新增 manager SLA：老板消息 60 秒内必须有事实或调度回执。
- 超过 1 分钟的动作自动转成 worker Run。
- manager 只保留 intake、routing、gate、boss brief。
- worker 不允许公开刷“收到/继续/待命”，只回 manager。

### P2：让 UI/代码任务进入受控自修复

- UI 子迭代启动必须生成 `stable-baseline.json`。
- 每轮最多 1-3 个 P0/P1。
- 每轮必须有 current screenshot、target screenshot、diff table、score。
- 更差自动回滚，不继续补丁。
- 两轮只剩 P2 或审美判断，交老板 A/B，不再自动修。

### P3：让跨团队从“群聊协作”变成“输入包协作”

- WebsiteChuhai 输出 Strategy Package。
- TODO002 输出 Demand Evidence Pack。
- Work Assistant 输出 Work Context Packet。
- ProductLab 输出 Product Run。
- 所有跨团队输入必须被主责 manager review 后才能进入执行。

### P4：云上分热度

- hot：router/watchdog alive，manager heartbeat <10m，worker heartbeat <30m，remote snapshot <10m。
- warm：router/watchdog alive，但员工需唤醒。
- cold：只有快照或守护在，不能接管。

老板视角不能再把 warm/cold 写成“云上团队稳定处理”。

### P5：导师进化飞轮

- 把 AI 刘小排 / AI 亦仁固定成 Mentor Board，而不是临时救火顾问。
- 每周至少一次团队级复盘问题进入导师闭环：本周最大返工、最大误判、最大机会。
- 每次导师反馈必须落到 `Decision / Task / Gate / SOP Patch / Anti-pattern` 之一。
- TODO002 负责导师工位、提问、顾问卡和 loop-state；主责团队 manager 负责翻译和执行闭环。
- ProductLab / WorkAssistant / WebsiteChuhai 不能直接拿导师原文派活，必须先形成 manager translation。
- 老板只看导师层结论和执行后证据，不看长文原文。

## 6. 你未来的人类工作边界

你要升级成“产品架构师/组织 owner”，不是回到监工。

你必须做：

- 定义 mission lane。
- 指定唯一 owner。
- 拍板目标图/目标状态/验收视口。
- 决定 P2 审美问题是否继续。
- 授权账号、支付、部署、外发。
- 做机会/方向/商业取舍。
- 对导师层的重大方向分歧做最终拍板。

系统和团队必须替你做：

- 聊天转 Issue。
- Issue 拆 Run。
- Run 产 Artifact。
- Artifact Gate。
- worker 催办和熔断。
- 证据存在性校验。
- 旧口径 stale。
- 跨团队投递回执。
- 云上新鲜度判断。
- AI 导师提问、顾问卡保存、manager 翻译、SOP/gate 反向更新。

## 7. 最小新规则

> AI 团队不是无限优化机器，也不是群聊里的员工模拟器。它必须是一个有任务状态机、证据内核、唯一 owner、事故熔断和老板例外机制的组织操作系统。

老板只看决策面。系统自己处理过程面。任何需要老板反复纠偏才能维持正确方向的任务，都应自动降级为架构事故，而不是继续让老板当监工。
