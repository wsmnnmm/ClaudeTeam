# AI 员工团队黄金机器门禁

目标：把最容易消耗老板的“你到底做没做完”从人工纠偏变成机器拦截。

## 已落地门禁

1. `task done` / `task update --status 待验收|已完成` 必须有真实 artifact。
2. worker `send --done` 必须带 artifact，且本地文件必须存在或 URL 看起来是真链接。
3. `manager_watch` 不再把 `待验收` 当 worker 仍在执行，避免反复催错对象。
4. `fleet-health` 会扫描各队 `state/tasks.json`：`待验收/已完成` 但 artifact 缺失直接红灯。

## 黄金门禁清单

| 编号 | 门禁 | 机器动作 | 人类只处理 |
|---|---|---|---|
| G1 | 完成证据 | 缺 artifact 不准 `待验收/已完成` | 判断 artifact 质量 |
| G2 | 页面还原 | 截图、预览链接、非白屏 probe、真实数据来源缺一则不准完成 | 判断视觉是否达标 |
| G3 | 跨团队投递 | 缺目标侧回执不准说“已同步” | 决定是否换通道或升级 |
| G4 | 导师双入口 | 问题生成后校验是否单导师入口；混合 prompt 直接失败 | 判断导师意见如何采纳 |
| G5 | 决策留痕 | 关键 manager 决策必须写 `log manager decision` | 拍最终方向 |
| G6 | 重复刷屏 | 无新事实、新证据、新 blocker、新状态流转则不发老板 | 要求额外状态时才打断 |
| G7 | 权限/账号 | 注册、登录、扫码、绑卡、key、付款必须老板动作卡 | 完成敏感动作 |

## 失败时怎么处理

- 红灯不是让老板补细节，而是 manager 先定位：缺文件、缺链接、缺权限、还是假完成。
- 如果是缺证据，任务退回 `进行中` 或重新派工，不能让老板继续验收空气。
- 如果是证据质量争议，manager 写决策日志：采纳、退回、二次问导师或升级老板。
