# Manager 决策日志协议

目标：让 manager 像“小老板”一样留下可追溯判断，而不是让老板在群聊里反复拼上下文。

## 什么时候必须写

- 改 owner、范围、优先级、截止时间。
- 把 worker 结果判为通过、退回、暂停或二次派工。
- 采纳或不采纳 AI 刘小排 / AI 亦仁建议。
- 决定继续、暂停、收窄、换方向、升级老板。
- 新增或修改验收门禁、SOP、反模式。

## 写在哪里

短期审计写 log：

```bash
claudeteam log manager decision "决策: <选项>; 原因: <证据>; owner: <谁>; 下一步: <动作>" <ref>
```

长期有效写 memory：

```bash
claudeteam remember manager decision "<长期有效的取舍/边界>" --ref <om_xxx-or-T-id>
```

## 决策卡格式

```text
决策：
原因：
证据：
未采纳：
Owner：
下一步：
需要老板：
复盘点：
```

## 质量线

- 不能只写“继续推进”“已优化流程”。
- 必须能回答：为什么这么判、谁接、交付什么、怎么验。
- 导师意见进入执行前，必须有 manager 决策日志说明采纳/不采纳。
- 老板只看需要他拍板的 1-3 个选项；其余决策由 manager 留痕并推进。
