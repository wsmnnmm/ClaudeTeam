# AI 导师双入口请求模板

目标：老板在任意团队群里说“问刘小排 / 问亦仁 / 请教导师”时，团队能稳定进入导师链路，但不混角色、不乱开新对话、不把内部协议发给导师。

## 总规则

- AI 刘小排和 AI 亦仁是两个独立入口、两份问题文件、两张顾问卡。
- 刘小排适合产品、MVP、技术实现、增长实验、指标、流程门禁和最小迭代。
- 亦仁适合商业判断、机会取舍、目标用户、付费意愿、节奏、长期主义和是否该停。
- 同一主题要问两位导师时，manager 先生成两段自然提问；收到两张卡后再合并判断。
- manager 不能把导师原文直接派给 worker，必须翻译成任务卡、门禁、SOP patch、反模式或老板决策卡。

## 导师可见文本

发给导师的内容必须像真人请教：

- 不写 Markdown 标题、表格、代码块和长项目清单。
- 不写“这是单独入口”“不要模拟另一位导师”“不要替另一位导师回答”“你是 AI 导师”这类内部边界。
- 不把本地路径、脚本名、任务卡协议、TODO002 执行要求直接贴给导师；必须压缩成自然背景。
- 如果老板说的是 AI 员工团队、ClaudeTeam、飞书机器人、Hermes Agent、平台账号协作，必须明确写这是 AI-agent operating team，不要让导师误解成招真人或传统组织扩张。

## 新开 / 追问

- 是否新开对话由 manager 判断并记录，不再默认新建。
- 同一导师、同一项目、同一主题，且有新执行证据、用户反馈、截图、数据或反证时，优先追问同一线程。
- 新项目、新主题、跨导师、上下文不干净、老板明确要干净重问，或 manager 无法确认当前线程是否相关时，才新开。
- 真正调用 TODO002 导师脚本时，必须显式写 `--conversation new|followup` 和 `--conversation-reason`。
- `followup` 必须绑定上一张导师卡的精确 `Source` URL；发送前当前页面会话 ID 必须和上一轮一致，执行后最终 URL 的会话 ID 也必须一致。URL 跳到新 ID 时，即使有回答也算失败，不得说追问成功。
- 老板手测的“你好，AI刘小排自我介绍”只算通道探针，不接业务问题。

## 群口令规则

老板在任意团队群里说“问刘小排 / 问亦仁 / 请教导师”，manager 直接整理上下文，不让老板补模板。

其他团队只提交 evidence pack，不直接维护导师登录态。真正调用导师由 TODO002 使用稳定 DeepSea 工位执行；成功和失败都必须回传源团队可见处。

## 图片规则

有图片就必须逐张写图片说明，说明这张图应该证明什么；不确定图片归属、疑似旧图或说明对不上时，先报 blocker，不上传。

## Manager 合并判断

manager 合并卡只给团队内部使用，必须包含：

```text
共识：
分歧：
刘小排建议落到哪些产品/执行动作：
亦仁建议落到哪些商业/组织动作：
采纳：
不采纳：
manager 推荐：
需要老板拍板：
下一轮证据：
```
