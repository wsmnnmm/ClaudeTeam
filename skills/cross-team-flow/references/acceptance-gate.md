# Acceptance Gate

A cross-team flow is accepted only when the process can be repeated without the
boss reconstructing context from chat.

## Evidence Ladder

Mark each layer independently:

- **Received**: source signal entered the correct team/router/inbox.
- **Understood**: manager saw parent context, prior memory, task ledger, and runtime.
- **Dispatched**: owner and supporting workers were assigned bounded tasks.
- **Executed**: at least one concrete command/browser/API/doc/Base action happened.
- **Artifacted**: output exists as a link, file, image, card, task update, or Base row.
- **Verified**: manager checked the artifact and named remaining risk.
- **Installed**: reusable rule entered skill/SOP/memory/cockpit when applicable.
- **Visible**: boss can see the canonical state without searching group chat.

## Stable-Flow Claim

Use these words precisely:

- "单次通道跑通": one successful message/feedback round trip.
- "流程可复用": context packet, owner, workstation, evidence gate, and memory/SOP are installed.
- "已在云上生效": cloud code/config is synced, cloud daemon loaded it, and cloud health/evidence passed.
- "待复测": implementation exists but a second real scenario has not confirmed it.

## Required Report Shape

```markdown
结论: <single sentence>
证据: <message id/task id/artifact/cloud health/Base row>
下一步: <owner + action + expected artifact>
需要老板: <none or one concrete action>
```
